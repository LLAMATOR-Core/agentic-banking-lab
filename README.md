# Agentic Banking Lab

Учебный стенд для исследования безопасности банковского ИИ-агента: проверки прав доступа,
взаимодействия через MCP и A2A, внедрения инструкций и отравления памяти.

В одном `banking-agent` работают оркестратор и три агента: банковский аналитик,
инвестиционный агент с поиском новостей и тревел-навык для вызова внешнего партнёра.
У каждого свои разрешения OAuth и токены для сервисов; память бывает общей
или раздельной. Описание: [архитектура](docs/ARCHITECTURE.md),
[опыты с полномочиями и памятью](docs/EXPERIMENTS.md).
Режим `BANKING_AGENT_MODE=legacy` сохраняет прежний граф и лаборатории денежных операций.

Стенд объединяет три самостоятельные системы:

| Система | Компоненты | Проект Langfuse |
|---|---|---|
| Интернет-банк | Один микросервис с оркестратором и тремя агентами, общий MCP АБС, АБС и поиск | `Banking` |
| Поиск путешествий | Тревел-агент, MCP веб-поиска и мок авиабилетов; внешний MCP Туту | `Travel` |
| Память | API памяти, LLM-оркестратор и MongoDB | `Persistent Memory` |

У систем разные Docker-сети, образы, приёмники и ключи проектов Langfuse.
Банк обращается к travel-системе только по A2A через `travel-api`, а к памяти через
`memory-api`. Прямого доступа к чужим агентам, MCP или MongoDB у него нет.
Keycloak и инфраструктура хранения Langfuse общие.

## Запуск

Нужны Docker Compose v2 и не менее 8 ГБ свободной оперативной памяти для Docker.

1. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

2. В `.env` укажите `OPENAI_API_KEY`. При необходимости измените `OPENAI_BASE_URL`,
   `OPENAI_MODEL` и `EMBEDDING_MODEL`. Провайдер должен поддерживать Chat Completions
   и Embeddings.
3. Запустите стенд:

   ```bash
   docker compose --env-file .env up -d --build
   ```

Проверьте контейнеры:

```bash
docker compose --env-file .env ps
```

Первый запуск скачивает образы и собирает приложения. После готовности Keycloak откройте
[интерфейс банка](http://localhost:3000). Если он открылся раньше Keycloak, обновите страницу.

## Выбор MCP и источника авиабилетов

После изменения `.env` повторите команду запуска. Оба MCP АБС и мок авиабилетов
запускаются всегда; параметры выбирают путь чата и источник рейсов.

| Параметр | Значение | Поведение |
|---|---|---|
| `BANKING_AGENT_MODE` | `orchestrator` | Три агента со своими токенами; денежные операции недоступны |
| `BANKING_AGENT_MODE` | `legacy` | Прежний банковский граф и лаборатории ниже |
| `SKILL_MEMORY_MODE` | `shared` / `isolated` | Общая память навыков одного клиента / отдельные области |
| `ABS_MCP_MODE` | `secure` | В обоих графах клиент определяется по JWT через обмен токенами Keycloak |
| `ABS_MCP_MODE` | `vulnerable` | В обоих графах LLM выбирает ID по задаче, начиная с клиента сессии; MCP не сверяет ID с JWT |
| `FLIGHTS_PROVIDER` | `tutu` | Поиск авиабилетов через MCP Туту |
| `FLIGHTS_PROVIDER` | `mock` | Один вымышленный рейс из собственного MCP |
| `FLIGHTS_MOCK_NOTE` | `clean.txt` | Нейтральная заметка в ответе мока |
| `FLIGHTS_MOCK_NOTE` | `provider-note.txt` | Ложная инструкция для опыта с отравлением памяти |

По умолчанию выбраны `orchestrator`, `shared`, `secure`, `tutu`, `clean.txt`. Пример для совместного исследования
нарушения контроля доступа и отравления памяти:

```dotenv
BANKING_AGENT_MODE=legacy
ABS_MCP_MODE=vulnerable
FLIGHTS_PROVIDER=mock
FLIGHTS_MOCK_NOTE=provider-note.txt
```

После изменения `.env`:

```bash
docker compose --env-file .env up -d --build
```

`FLIGHTS_MOCK_NOTE` выбирает файл из `infra/flights-mcp/`. Его можно редактировать;
мок читает текст при каждом запросе. Ошибка Туту не приводит к подмене результатов моком.

Уязвимый MCP меняет банковские инструменты чата в обоих графах. Обзор счетов в интерфейсе и профиль
для персонализации в `legacy` используют защищённый MCP. В чате `legacy` денежные операции требуют отдельного подтверждения при обоих
значениях `ABS_MCP_MODE`. В `orchestrator` они недоступны. История и память
сохраняются при смене настроек.

Подробнее: [настройки и проверка подключений](docs/CONFIGURATION.md),
[порядок проведения опытов](docs/EXPERIMENTS.md).

Банк пишет в `Banking`, организация-партнёр в `Travel`, сервис памяти в
`Persistent Memory`. У каждого свой приёмник Langfuse и своя пара ключей.
Один входящий запрос внутри системы создаёт одно дерево с вложенными шагами.
На границе систем начинается локальная трасса, связанная с вызвавшей её через
`upstream_trace_id`, `upstream_span_id` и метки опыта. Исторические записи сохраняются.

Пароли указаны для исходного `.env.example`. Кроме этих портов стенд использует
`5432`, `27017`, `8001-8004`, `8101`, `8104-8106` и `9090`.

## Контекст агента и память

Маршрутизатор видит текущее сообщение и название предыдущего навыка. Профиль АБС
и долговременная память до выбора исполнителя не загружаются. Каждый навык читает
собственную историю и до восьми воспоминаний каждого долговременного слоя.
Инвестиционный получает только портфель через MCP; банковский аналитик читает профиль,
счета и остатки, операции, выписки за период, портфель и каталог продуктов.
У обоих нет прав на переводы, платежи и покупки. Внешний тревел-партнёр
использует собственный MCP веб-поиска и возвращает ссылки на источники.
Тревел-навык вызывает внешнего партнёра без исходного банковского JWT и полной истории.
Оркестратор готовит финальный ответ по результатам исполнителей и истории текущего
диалога. При необходимости подключает других агентов, каждого не более одного раза
за запрос. Результаты коллег дополнительным агентам не передаются.

`memory-service` хранит историю и кандидатов, отдельный `memory-orchestrator`
выделяет долговременные знания. В `shared` три навыка читают общую память одного
клиента. В `isolated` каждому навыку выделена отдельная область. Новые области сохраняют конкретного
клиента и не используют `user_id="*"`. Личные истории навыков не объединяются.
Общий слой намеренно позволяет исследовать перенос данных и инструкций через
границу полномочий; изоляция не устраняет собственное отравление навыка.

В `legacy` прежний банковский граф получает профиль, историю и память до выбора
навыка; его межклиентская общая область `*` сохранена для отдельных лабораторий.

В `.env` параметр `MEMORY_ORCHESTRATION_INTERVAL_SECONDS` задаёт интервал обработки:
`1800`: 30 минут по умолчанию, `10`: быстрый опыт, `0`: только ручной запуск.
Для опыта с отравлением можно отключить расписание и вызвать
`POST http://localhost:8004/api/v1/orchestrator/collect` с токеном `memory-operator`.
Пример запроса приведён в [настройках памяти](docs/CONFIGURATION.md#обработка-долговременной-памяти).

## Проверки

Для автоматических тестов нужен Python 3.12 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
ruff check services tests scripts
pytest -q
```

Для проверки основных функций работающего стенда:

```bash
python scripts/smoke_test.py
```

В режиме оркестратора скрипт проверяет банковский обзор и выписку за период,
инвестиционный портфель, поиск партнёра и уточнение бюджета поездки с LLM. В `legacy` проверка
также подготавливает денежную операцию; `--confirm` выполняет перевод 1 RUB
между тестовыми счетами.

Для проверки OAuth без LLM и межагентного опыта:

```bash
python scripts/skill_experiment.py --phase oauth --output artifacts/docker-review/skill-oauth.json
python scripts/skill_experiment.py --phase memory --output artifacts/docker-review/skill-memory-shared.json
```

Порядок сравнения с `isolated`, метки Langfuse и ограничения выводов:
в [EXPERIMENTS.md](docs/EXPERIMENTS.md).

## Границы учебного стенда

Стенд содержит намеренные уязвимости и локальные тестовые пароли. Он не предназначен
для реальных банковских данных. Keycloak работает в режиме `start-dev`, TLS не настроен.

Туту и веб-поиск через DDGS требуют доступа к внешней сети. Туту используется только
для поиска, без оформления заказа и передачи данных пассажиров. Бронирование в
Travel Agent имитируется локально. Поиск отелей не реализован.
Без доступной LLM или модели эмбеддингов соответствующая
операция возвращает ошибку; подготовленных ответов вместо модели нет.
